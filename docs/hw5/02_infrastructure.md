# Шаг 2. Выбор инфраструктуры: Supabase

| Критерий | Supabase (вариант A) | Свой PostgreSQL в Docker на VPS (вариант B) |
|---|---|---|
| Стоимость | бесплатный тариф: 500 МБ базы, 50 000 пользователей в месяц — с запасом для семейного приложения | VPS от ~300 ₽/мес |
| База данных | PostgreSQL — та же, что в варианте B | PostgreSQL |
| Вход пользователей | готовый Supabase Auth (email и пароль, подтверждение почты, сброс пароля) | писать самим |
| API | создаётся автоматически по таблицам (PostgREST) + наши SQL-функции | писать самим |
| Защита данных | Row Level Security — правила доступа прямо в базе | писать проверки в коде сервера |
| Обновление в реальном времени | Supabase Realtime (FR-3.13) | писать самим |
| Администрирование | обновления, бэкапы и HTTPS делает Supabase | всё самим |

**Выбор — Supabase.** Он закрывает все требования ТЗ (вход, права, API, обновления в реальном
времени) без собственного сервера, бесплатно и без администрирования. Стек с Supabase был
зафиксирован ещё в ТЗ (ДЗ3) и в правилах агента (CLAUDE.md, правило 5).
Ограничение бесплатного тарифа: проект «засыпает» после 7 дней без запросов — его
просыпают одной кнопкой в панели Supabase; для учебного проекта это приемлемо.
