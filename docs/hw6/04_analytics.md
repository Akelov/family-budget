# Шаг 4. Аналитика: Яндекс.Метрика

## Почему Метрика

Бесплатна, работает в России, есть цели (события), карта кликов и отчёты по конверсиям.

## Как подключено

| Что | Где |
|-----|-----|
| Загрузка счётчика без inline-скрипта (его запретила бы CSP): очередь `window.ym` + `tag.js` | `shared/lib/analytics.ts` — `initAnalytics` |
| Номер счётчика — переменная `VITE_YANDEX_METRIKA_ID` (GitHub → Variables), только для production: превью не засоряют статистику | `.github/workflows/ci.yml` |
| Просмотры страниц в одностраничном приложении: при каждой смене пути `ym('hit', …)` | `app/routerAnalytics.ts` |
| CSP разрешает `mc.yandex.ru`, `mc.yandex.com`, `yastatic.net` | `vercel.json` |
| Без номера счётчика (локально, тесты, демо) все функции ничего не делают | `parseCounterId` |

## События (цели)

| Событие | Когда | Параметры |
|---------|-------|-----------|
| `sign_up` | регистрация | — |
| `login` | вход по email | — |
| `login_google` | старт входа через Google | — |
| `household_created` | создана семья | — |
| `invite_created` | создано приглашение | `role`: admin / member |
| `invite_accepted` | принято приглашение | — |
| `transaction_created` / `transaction_updated` | операция добавлена / изменена | `type`: income / expense |
| `transaction_deleted` | операция удалена | — |
| `budget_created` | создан бюджет | — |

В Метрике заведены цели «JavaScript-событие» для пяти главных: `sign_up`, `transaction_created`,
`budget_created`, `invite_accepted`, `login_google`.

## Приватность

Данные о деньгах семьи — личные, поэтому:

- в события не передаются суммы, комментарии, имена, email; параметры — только категории из
  фиксированного списка (тип операции, роль) — это закреплено типом `GoalParams`;
- **Вебвизор выключен** — он записывал бы экран с суммами;
- из адресов страниц отрезаются параметры (`?next=…`), код приглашения заменяется на
  `/invite/:token` (`pageUrlForAnalytics`).

## Как AI помогал с событиями

Агент предложил список событий по воронке продукта (регистрация → семья → первая операция →
бюджет → приглашение второго участника), исключил события с личными данными и проверил
подключение в браузере (Playwright): очередь содержит `init` с `webvisor:false` и просмотры
`/login`, `/invite/:token` — без параметров и кода приглашения; 0 нарушений CSP.

## Проверка

| Что | Результат |
|-----|-----------|
| Визиты в Метрике | ✅ 2 визита 17.10 (Отчёты → Посещаемость) |
| Цели | заведены 5 целей; в браузере владельца продукта Метрику блокирует расширение (`net::ERR_BLOCKED_BY_CLIENT`) — события из этого браузера не доходят. Сайт при этом работает: сбой аналитики ничего не ломает |
| Тесты | `analytics.test.ts` (номер счётчика, очистка адреса, работа без счётчика), `routerAnalytics.test.ts` (первая страница, смена пути, повтор пути, отписка) |

Вывод для продукта: заметная доля пользователей блокирует аналитику, поэтому цифры Метрики —
нижняя оценка, а не точное число.
