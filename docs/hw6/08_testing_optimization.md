## Оптимизация производительности

### Как измеряли

Lighthouse 12 (мобильный профиль: медленный 4G, слабый процессор) на собранном сайте,
отданном локальным сервером «как Vercel»: те же заголовки из `vercel.json` и сжатие brotli.
Страница — `/login` (её первой видит каждый новый посетитель).

### Рекомендации AI и что применили

AI-агент разобрал состав файлов сборки (source map) и отчёт Lighthouse:

| Рекомендация | Решение | Почему |
|--------------|---------|--------|
| Вынести Supabase (≈ 80 % основного файла) в отдельный файл | ✅ применено (`manualChunks` → `supabase`) | библиотека меняется только при обновлении версии; после каждой публикации браузер перекачивает **27 КБ** нашего кода вместо **85 КБ** |
| Убрать демо-режим (мок-данные) из рабочей сборки | ✅ режим данных стал константой сборки (`define: __SUPABASE_ENABLED__`) | проверка показала, что сборщик и раньше выбрасывал мок-данные; выигрыш по размеру ≈ 0, но теперь это гарантировано, а не случайно |
| Контраст основного зелёного цвета 4,41 < 4,5 (WCAG AA) | ✅ `#33875c` → `#2f8257` (4,72) | доступность для слабовидящих |
| Нет `robots.txt` (Vercel отдавал вместо него страницу сайта) | ✅ `public/robots.txt` | SEO, ссылки-приглашения не индексируются |
| Кэш для файлов `/assets/` на год | ✅ сделано ещё на шаге 2 (`Cache-Control: immutable`) | имена файлов содержат хеш версии |
| Раздел «Отчёты» с графиками (91 КБ) грузить только при открытии | ✅ уже было (`React.lazy`, ДЗ4) | — |
| Разместить шрифт Inter на своём сайте вместо Google Fonts | ❌ отложено | нужна новая зависимость (`@fontsource/inter`) — по правилу 5 CLAUDE.md только после согласования |
| Загружать Realtime только после входа | ❌ отложено | supabase-js подключает Realtime внутри клиента; выигрыш ~20 КБ не стоит переписывания |
