# Проверка ТЗ AI-агентом (Шаг 6)

## Как проводилась проверка

ТЗ, User Stories и описание продукта были отданы на ревью **отдельному запуску Claude Code**
(`claude -p`) в чистой сессии: агент не участвовал в написании ТЗ и видел только эти три файла,
с правами только на чтение.

- Промпт ревью (RTCF): [tz_review_prompt.md](tz_review_prompt.md)
- Сырой ответ агента на первой редакции: [tz_review_result.md](tz_review_result.md)

**Итог первого ревью:** 20 замечаний (3 критичных, 13 важных, 4 мелких), оценка готовности **6/10**.

## Собственная проверка после правок

Примеры из приложения C я пересчитал отдельным скриптом по формуле FR-5.5 и FR-7.4.
Один пример оказался неверным: для цикла с 29-го и даты 28.02.2026 период начинается
28 февраля (в феврале 2026 года 28 дней), а не 29 января. Пример исправлен и дополнен
соседним случаем (27.02.2026). Поскольку эти примеры станут тестами в ДЗ4, ошибка
в них дала бы неверный тест.

## Повторное ревью

Исправленное ТЗ снова отдано на ревью новому чистому запуску агента с тем же промптом.
Сырой ответ: [tz_review_result_v2.md](tz_review_result_v2.md).

**Итог: оценка 7/10** (была 6/10). Агент сам пересчитал примеры из приложения C и подтвердил,
что они верны. Новые замечания уже не о пропущенных функциях, а о деталях реализации.

**Исправлено сразу (4 критичных и 4 важных):**

| Замечание | Решение |
|---|---|
| «Отменить» после физического удаления теряет автора, теги и `created_at` | Мягкое удаление (`deleted_at`), RPC `delete_transaction` / `restore_transaction` (FR-3.6, §3.3) |
| «Нет прав» и «конфликт» неразличимы при пустом ответе | Изменение только через `update_transaction` с кодами `P0403` / `P0409` / `P0404`; `updated_at` обновляет триггер (FR-3.5, ERR-6 – ERR-8) |
| Нет схемы параметров адреса | FR-3.14: `mode`, `from`, `to`, `q`, `type`, `cat`, `sub`, `tag`, `author`; приоритет адреса над личным видом; стрелки для `range`; лимит 5 лет |
| Критерий готовности противоречит объёму, ДЗ6 без требований | §7: готовность = Must + Should; интеграции ДЗ6 описываются отдельно |
| Восстановление категории неоднозначно | FR-2.4: восстанавливаются подкатегории, архивированные вместе с ней |
| Изменение операции с архивной подкатегорией | FR-2.6: архивная подкатегория показывается и сохраняется без изменений |
| ERR-1: неактивная кнопка противоречит переводу фокуса | Кнопка всегда активна, ошибки — после ухода с поля и при сохранении |
| Расхождение «Настройки › Период» и раздела «Семья» | US-16 исправлена |

**Открытые вопросы — решаются при реализации (ДЗ4–ДЗ5):** типы параметров и ответов RPC,
полный словарь текстов интерфейса, HEX-палитра `cat-1…cat-12` и набор иконок для выбора,
жизненный цикл архивных бюджетов, права на отдельные колонки `members` (запрет менять себе
роль) и соответствующие автотесты RLS, мок-данные для ДЗ4, настройки Supabase (адреса возврата,
Realtime), метрики проверки NFR-G4/G5/G7. Эти пункты не меняют функционал, а уточняют
реализацию, поэтому будут закрыты в коде и документации следующих ДЗ.

## Вывод

Ревью отдельным агентом оказалось полезным: за два прохода найдено 40 замечаний, из них
7 критичных — права доступа, модель данных для конфликтов и дублей, поведение бюджетов
при разных периодах, отмена удаления. Все они привели бы к ошибкам в коде или к тому, что
AI-агент принял бы решения о безопасности сам. Независимая проверка тоже понадобилась:
один из тестовых примеров, которые я написал, был неверным, и это нашёл пересчёт, а не
ревью.
