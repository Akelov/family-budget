## 1. Описание проекта

«Семейный бюджет» — веб-приложение (SPA), адаптированное под телефон, для совместного учёта
доходов и расходов семьи. Участники записывают операции с обязательной категорией
и подкатегорией, смотрят историю и сводку за период, отчёты с раскрытием до подкатегорий,
ведут бюджеты по наборам подкатегорий. Отчётный период — календарный месяц, свой цикл
«с N-го числа» или произвольный диапазон.

**Стек:** React 19 + TypeScript (strict) + Vite, Tailwind CSS v4, React Router, Recharts,
`lucide-react` (иконки); Supabase (PostgreSQL, Auth, Row Level Security, REST, RPC, Realtime);
Vercel; GitHub Actions; тесты — Vitest и Testing Library.

**Вне рамок версии 1.0:** цели накоплений, регулярные и плановые операции, прогноз, выгрузка
в Excel, тёмная тема, счета и переводы, мультивалютность, интеграция с банками, нативные
приложения, офлайн-режим (PWA), несколько семей у одного пользователя, передача роли
владельца, удаление аккаунта и выгрузка персональных данных (учебный проект; для продакшена
потребуется учесть 152-ФЗ).

### 1.1. Глоссарий

| Термин | Значение |
|---|---|
| Семья (household) | Общее пространство учёта; у пользователя в v1.0 одна активная семья |
| Участник (member) | Пользователь в семье с ролью `owner`, `admin` или `member` |
| Операция (transaction) | Доход или расход: сумма, подкатегория, дата, комментарий, теги, автор |
| Категория / подкатегория | Двухуровневый справочник; тип категории — `income` или `expense` |
| Тег | Метка семьи, произвольно прикрепляемая к операциям |
| Период | Интервал дат `[start, end]` включительно, по которому считаются история, сводка, отчёты и бюджеты |
| Режим периода | `month` — календарный месяц; `cycle` — с дня N; `range` — произвольный диапазон |
| Период семьи | Период по общему режиму семьи (без личного вида и диапазона) |
| Бюджет | Сумма на каждый период семьи по набору подкатегорий расходов |
| «Сегодня» | Локальная дата устройства пользователя (`YYYY-MM-DD`) |

## 2. Целевая аудитория

Семьи и пары 25–45 лет с общим бюджетом; учёт ведут 2–4 человека (максимум 10), в основном
с телефона. Персоны — в [user_stories.md, раздел 1](user_stories.md#1-роли-personas).

| Роль | Кто | Права (кратко, полностью — §3.2) |
|---|---|---|
| Владелец (`owner`) | создатель семьи, ровно один | всё, включая участников, приглашения и удаление семьи |
| Администратор (`admin`) | доверенный взрослый | настройки учёта, период семьи, бюджеты, любые операции |
| Участник (`member`) | например, ребёнок | свои операции, просмотр всего остального |

## 3. Данные и права

### 3.1. Модель данных

Деньги — `numeric(12,2)`, всегда положительные; знак задаёт `type`. Даты операций — `date`.
Все таблицы: `id uuid`, `created_at timestamptz`, изменяемые — `updated_at timestamptz`
(обновляется триггером; используется для проверки конфликтов, ERR-8). Таблицы данных семьи содержат `household_id`.

| Таблица | Ключевые поля | Ограничения и поведение |
|---|---|---|
| `households` | `name`, `period_mode` (`month`/`cycle`), `period_start_day` (1–31) | `name` 1–50 символов; удаление семьи каскадно удаляет все её данные |
| `members` | `household_id`, `user_id`, `role`, `display_name`, `personal_period_mode` (`null`/`month`/`cycle`), `personal_period_start_day`, `removed_at` | среди активных (`removed_at is null`): пара `(household_id, user_id)` уникальна, ровно один `owner` на семью, пользователь — не более чем в одной семье; строка не удаляется при исключении, чтобы сохранить имя автора |
| `invites` | `household_id`, `token`, `role` (`admin`/`member`), `expires_at`, `revoked_at`, `used_at`, `used_by` | одноразовое; срок 7 дней; не более 10 активных участников в семье |
| `categories` | `household_id`, `type` (`income`/`expense`), `name`, `color`, `icon`, `archived_at` | уникально `(household_id, type, lower(trim(name)))`; `on delete cascade` для подкатегорий |
| `subcategories` | `category_id`, `name`, `archived_at` | уникально `(category_id, lower(trim(name)))` |
| `transactions` | `id` (генерирует клиент), `household_id`, `type`, `amount`, `subcategory_id`, `date`, `comment`, `author_id` → `members.id`, `deleted_at` | мягкое удаление: строки с `deleted_at` не видны нигде, кроме восстановления; `amount > 0`; `type` = тип категории подкатегории (триггер); `date` не позже текущей даты сервера + 1 день (запас на часовые пояса); `comment` ≤ 500 символов; `on delete restrict` для подкатегории |
| `tags` | `household_id`, `name` | уникально `(household_id, lower(trim(name)))`; `name` 1–30 символов |
| `transaction_tags` | `transaction_id`, `tag_id` | первичный ключ из пары; не более 10 тегов на операцию (триггер); `on delete cascade` с обеих сторон |
| `budgets` | `household_id`, `name`, `amount`, `archived_at` | `amount > 0` |
| `budget_items` | `budget_id`, `category_id` **или** `subcategory_id` | ровно одно из двух; только расходные (триггер); категория = все её подкатегории, включая добавленные позже |
| `client_errors` | `household_id`, `level`, `screen`, `code`, `message` | только вставка с клиента (§6.4) |

Индексы: `transactions (household_id, date desc)`, `transactions (subcategory_id)`,
`transaction_tags (tag_id)`.

Чтение — для всех активных участников своей семьи, если не указано иное. Права проверяются

| Объект | Действие | `owner` | `admin` | `member` |
|---|---|:-:|:-:|:-:|
| Семья | переименовать | ✅ | ✅ | — |
| Семья | изменить период семьи | ✅ | ✅ | — |
| Семья | удалить | ✅ | — | — |
| Семья | выйти из семьи | — | ✅ | ✅ |
| Участники | смотреть список | ✅ | ✅ | ✅ |
| Участники | изменить роль, исключить | ✅ | — | — |
| Участник (себя) | изменить имя и личный вид периода | ✅ | ✅ | ✅ |
| Приглашения | смотреть, создать, отозвать | ✅ | — | — |
| Категории, подкатегории | смотреть | ✅ | ✅ | ✅ |
| Категории, подкатегории | создать, изменить, архивировать, удалить | ✅ | ✅ | — |
| Теги | смотреть, создать при записи операции | ✅ | ✅ | ✅ |
| Теги | переименовать, объединить, удалить | ✅ | ✅ | — |
| Операции | создать (автор = он сам) | ✅ | ✅ | ✅ |
| Операции | изменить, удалить свои | ✅ | ✅ | ✅ |
| Операции | изменить, удалить чужие | ✅ | ✅ | — |
| Бюджеты | смотреть | ✅ | ✅ | ✅ |
| Бюджеты | создать, изменить, архивировать | ✅ | ✅ | — |

### 3.3. Серверные функции (RPC)

Сводка, поиск, фильтры, отчёты и бюджеты считаются на сервере по **всем** операциям периода,
а не по загруженной на клиент порции.

| Функция | Параметры | Возвращает |
|---|---|---|
| `create_household(name)` | название | семью; в одной транзакции создаёт участника-владельца и готовый набор категорий |
| `accept_invite(token)` | токен | участника; проверяет срок, отзыв, использование и лимит участников |
| `list_transactions(period, filters, search, cursor)` | период, фильтры, строка поиска, курсор | порцию из 50 операций с категорией, подкатегорией, тегами и автором |
| `period_summary(period, filters, search)` | то же без курсора | `income`, `expense`, `balance` |
| `report_by_category(period, type)` | период, тип | категории с суммами |
| `report_by_subcategory(period, type, category_id)` | + категория | подкатегории с суммами |
| `report_by_tag(period, type)` | период, тип | теги с суммами |
| `budget_status(period_start, period_end)` | период семьи | бюджеты с потрачено/осталось/процентом/статусом |
| `update_transaction(id, expected_updated_at, fields)` | id, ожидаемый `updated_at`, новые поля | операцию; ошибки: `P0403` — нет прав, `P0409` — конфликт (изменена другим участником), `P0404` — не найдена |
| `delete_transaction(id)` / `restore_transaction(id)` | id | мягкое удаление и восстановление с теми же полями, тегами, автором и `created_at`; права как у изменения |

Денежные суммы в ответах RPC — в копейках (`bigint`); в рубли клиент переводит только для вывода.

## 4. Функциональные требования

### 4.1. Аккаунт и семья (US-01 – US-04)

| ID | Требование |
|---|---|
| FR-1.1 | Регистрация и вход по email и паролю (≥ 8 символов) через Supabase Auth, подтверждение email, выход, восстановление пароля по ссылке. |
| FR-1.2 | Пользователь без семьи после входа видит экран «Создать семью» (или принятие приглашения, если пришёл по ссылке); с семьёй — экран «Операции». |
| FR-1.3 | Создание семьи — `create_household`: название 1–50 символов; создатель становится `owner`; добавляется готовый набор категорий (приложение A). Имя участника по умолчанию — часть email до «@». |
| FR-1.4 | Владелец создаёт одноразовую ссылку-приглашение с ролью `admin` или `member` сроком 7 дней и может отозвать её. |
| FR-1.5 | Переход по `/invite/:token` без входа ведёт на вход или регистрацию; токен сохраняется в адресе возврата (в т. ч. в ссылке подтверждения email) и после входа принимается через `accept_invite`. |
| FR-1.6 | Владелец меняет роль участника (`admin` ↔ `member`) и исключает участников (`removed_at`). Роль `owner` не передаётся и не меняется. |
| FR-1.7 | Операции исключённого или вышедшего участника остаются; автор показывается как «<имя> (бывший участник)». |
| FR-1.8 | `admin` и `member` могут выйти из семьи («Настройки › Профиль») с подтверждением; после выхода видят экран «Создать семью». |
| FR-1.9 | Владелец может удалить семью: подтверждение вводом названия семьи; удаляются все данные семьи, у всех участников открывается экран «Создать семью». |

### 4.2. Категории и подкатегории (US-05)

| ID | Требование |
|---|---|
| FR-2.1 | Отдельные списки категорий для расходов и доходов; у категории — название, цвет из палитры из 12 цветов и иконка из набора (приложение A). |
| FR-2.2 | Активная категория всегда имеет хотя бы одну активную подкатегорию: новую категорию нельзя сохранить без подкатегории, последнюю активную подкатегорию нельзя архивировать или удалить. |
| FR-2.3 | Создание, переименование, архивирование и восстановление — `owner`, `admin`. |
| FR-2.4 | Архивирование категории архивирует все её активные подкатегории (с тем же `archived_at`); восстановление категории восстанавливает её и подкатегории, архивированные вместе с ней; подкатегорию архивной категории восстановить отдельно нельзя. |
| FR-2.5 | Удаление возможно, только если на категорию (подкатегорию) нет операций и ссылок из бюджетов; удаление категории удаляет её подкатегории. Иначе вместо «Удалить» — «В архив» с пояснением. |
| FR-2.6 | Архивные элементы скрыты из выбора при записи новой операции, но показываются в истории и отчётах с пометкой «в архиве» и продолжают учитываться в бюджетах. При изменении операции с архивной подкатегорией она показывается в форме с пометкой «в архиве» и сохраняется без изменений; выбрать другую архивную нельзя. |
| FR-2.7 | Названия уникальны в своей области без учёта регистра и пробелов по краям. |

### 4.3. Операции (US-06 – US-11)

| ID | Требование |
|---|---|
| FR-3.1 | Кнопка «+» доступна на всех основных экранах и открывает форму операции (на телефоне — нижний лист, на десктопе — модальное окно). |
| FR-3.2 | Поля формы: тип (по умолчанию «Расход»), сумма, категория → подкатегория (обязательна, список зависит от типа и категории), теги, дата (по умолчанию «сегодня», не позже «сегодня»), комментарий. |
| FR-3.3 | Сумма: число > 0, не более 2 знаков после запятой, не более 9 999 999 999,99; цифровая клавиатура; разделитель «,» или «.». |
| FR-3.4 | `id` операции генерирует клиент (UUID) при открытии формы: повтор сохранения с тем же `id` не создаёт дубликат. Автора задаёт сервер (текущий участник), а не клиент. |
| FR-3.5 | Изменять и удалять операцию могут её автор, `owner` и `admin`. Изменение — только через `update_transaction` с проверкой `updated_at`, чтобы «нет прав» (ERR-6) и «конфликт» (ERR-8) различались по коду. Автор при изменении не меняется. |
| FR-3.6 | Удаление — мягкое (`delete_transaction`), сразу, без диалога подтверждения; 5 секунд показывается тост «Операция удалена» с кнопкой «Отменить» (`restore_transaction`), которая возвращает операцию со всеми полями, тегами, автором и местом в истории. |
| FR-3.7 | Экран «Операции»: переключатель периода, сводка, поиск, фильтры, история. Период, поиск и фильтры хранятся в параметрах адреса (схема — FR-3.14), чтобы работали ссылки из отчётов и кнопка «Назад». |
| FR-3.8 | История за период сгруппирована по дням, новые сверху; заголовок дня — «Вторник, 14 октября 2026 г.»; внутри дня — по времени создания, новые сверху. Подгрузка порциями по 50 при прокрутке; при загрузке — скелетон. |
| FR-3.9 | Строка операции: иконка категории, «Категория › Подкатегория», комментарий, теги, автор, сумма по правилу NFR-G6: расход «−2 500 ₽» красным, доход «+95 000 ₽» зелёным. |
| FR-3.10 | Сводка (`period_summary`): Доход, Расход, Остаток = Доход − Расход по всем операциям периода с учётом поиска и фильтров; отрицательный остаток — красным со знаком «−»; при активных поиске или фильтрах подпись «по результатам поиска и фильтров». |
| FR-3.11 | Поиск без учёта регистра по комментарию, названиям категории, подкатегории и тегов; срабатывает через 300 мс после ввода. |
| FR-3.12 | Фильтры: тип, категории и подкатегории, теги, авторы (включая бывших участников); разные фильтры объединяются по «И», значения внутри фильтра — по «ИЛИ»; на кнопке «Фильтры» — число активных фильтров; кнопка «Сбросить». |
| FR-3.13 | Изменения других участников приходят через Supabase Realtime (подписка на `transactions` своей семьи): событие перезапрашивает сводку и первую порцию списка. Остальные справочники и права перезапрашиваются при возврате на вкладку; если участника исключили или семью удалили, показывается экран «Создать семью». |
| FR-3.14 | Схема параметров адреса: `mode` (`month`/`cycle`/`range`), `from`, `to` (`YYYY-MM-DD`, границы периода), `q` (поиск), `type` (`income`/`expense`), `cat`, `sub`, `tag`, `author` (списки `uuid` через запятую). Пример: `/?mode=cycle&from=2026-09-29&to=2026-10-28&sub=…`. Период из адреса важнее личного вида; стрелки листают в режиме `mode` (для `range` — на длину диапазона); кнопка «К текущему периоду» сбрасывает период. Длина `range` — не больше 5 лет. |

### 4.4. Отчёты (US-12, US-13, US-15)

| ID | Требование |
|---|---|
| FR-4.1 | Экран «Отчёты»: переключатель «Расходы / Доходы», период (§4.5), вкладки «Категории» и «Теги». |
| FR-4.2 | Уровень категорий: кольцевая диаграмма и список «категория — сумма — доля %», по убыванию суммы; в центре диаграммы — итог. |
| FR-4.3 | Нажатие на категорию открывает уровень подкатегорий с такой же диаграммой и списком; доли — внутри категории; кнопка «Назад». |
| FR-4.4 | Нажатие на подкатегорию открывает «Операции» с фильтром по ней и тем же периодом (через параметры адреса). |
| FR-4.5 | Доли округляются до целого процента; сумма долей приводится к 100% методом наибольшего остатка. |
| FR-4.6 | Вкладка «Теги» (Should): теги с суммой за период по выбранному типу; операция с несколькими тегами учитывается в каждом; под списком — пояснение. Нажатие на тег открывает «Операции» с фильтром по нему. |

### 4.5. Отчётный период (US-16, US-17)

| ID | Требование |
|---|---|
| FR-5.1 | Режимы: `month` (с 1-го по последний день), `cycle` (с дня N, 1–31), `range` (две даты включительно). |
| FR-5.2 | Режим семьи (`month` или `cycle`) задают `owner` и `admin`; по умолчанию `month`. |
| FR-5.3 | Участник может включить личный вид (`month` или `cycle` со своим N) или вернуться к «Как у семьи»; на других это не влияет. Личный вид действует в «Операциях» и «Отчётах». |
| FR-5.4 | `range` выбирается на экране для разового просмотра «Операций» и «Отчётов» и не сохраняется в настройках. |
| FR-5.5 | Период `cycle`, содержащий дату D. Пусть `s(Y, M) = min(N, дней в месяце M года Y)`. Если `день(D) ≥ s(год D, месяц D)`, начало = `s` текущего месяца D, иначе начало = `s` предыдущего месяца. Конец = день перед началом следующего периода. Примеры — приложение C. |
| FR-5.6 | Стрелки ‹ › листают периоды текущего режима. Подписи: `month` — «Октябрь 2026»; `cycle` и `range` — «29 сентября – 28 октября 2026», через год — «29 декабря 2026 – 28 января 2027». |
| FR-5.7 | Выбранный период передаётся между «Операциями» и «Отчётами» через параметры адреса. |
| FR-5.8 | «План» всегда считается по **периоду семьи**: личный вид и `range` на бюджеты не действуют; в «Плане» подпись «Бюджеты считаются по периоду семьи: <период>». |

### 4.6. Теги (US-14)

| ID | Требование |
|---|---|
| FR-6.1 | В форме операции — поле тегов с автодополнением по тегам семьи; любой участник может создать новый тег из поля. |
| FR-6.2 | Не более 10 тегов на операцию; название 1–30 символов; совпадение без учёта регистра предлагает существующий тег. |
| FR-6.3 | `owner` и `admin` переименовывают, объединяют и удаляют теги. Объединение A → B: операции с A получают B (без дубликата, если B уже есть), A удаляется. Удаление тега снимает его с операций. Неиспользуемые теги не удаляются автоматически. |

### 4.7. Бюджеты (US-18, US-19)

| ID | Требование |
|---|---|
| FR-7.1 | Экран «План», вкладка «Бюджеты»: список активных бюджетов за период семьи (FR-5.8); стрелки ‹ › открывают прошлые периоды. |
| FR-7.2 | Создание и изменение (`owner`, `admin`): название, сумма > 0, набор из подкатегорий и/или целых категорий расходов (хотя бы один элемент). Изменение действует на все периоды, включая прошлые. |
| FR-7.3 | Потрачено = сумма расходов семьи за период по подкатегориям бюджета, включая архивные; Осталось = max(0, сумма − потрачено); Процент = ⌊потрачено × 100 / сумма⌋ (может быть больше 100). Расчёт в копейках. |
| FR-7.4 | Статус по копейкам, не по проценту: `потрачено > сумма` → «Превышен на N ₽» (красный); иначе `потрачено × 100 ≥ сумма × 80` → «Почти у лимита» (жёлтый); иначе «В норме». Примеры — приложение C. |
| FR-7.5 | Каждый период считается с нуля; остаток не переносится. |
| FR-7.6 | Нажатие на бюджет открывает «Операции» с фильтром по его подкатегориям и периодом семьи. |
| FR-7.7 | Если все подкатегории бюджета архивированы, бюджет показывается с пометкой «Нет активных подкатегорий». |

## 6. Обработка ошибок

Список ситуаций составлен с помощью AI-агента: по каждому экрану перебирались ошибки
валидации, пустые данные, сбои сети и сервера, отказ в доступе. Тексты сообщений — в
приложении B.

### 6.1. Общие правила

| ID | Ситуация | Код от сервера | Поведение | UX-решение |
|---|---|---|---|---|
| ERR-1 | Ошибка валидации поля | — (клиент) или `23514` | Сохранение не отправляется | Ошибка поля показывается после ухода с поля и при попытке сохранить: подсказка под полем красным, красная рамка; кнопка «Сохранить» всегда активна, при нажатии с ошибками фокус переходит на первое ошибочное поле |
| ERR-2 | Нет сети при сохранении | сетевая ошибка | Данные формы не теряются | Форма остаётся открытой, тост «Нет соединения» с кнопкой «Повторить»; повтор с тем же `id` не создаёт дубликат (FR-3.4) |
| ERR-3 | Нет сети при загрузке | сетевая ошибка | Показ последних загруженных данных из памяти (без хранения на устройстве) | Баннер «Нет соединения, данные могут быть неактуальны»; автоповтор при восстановлении сети |
| ERR-4 | Ошибка сервера | 5xx | **Чтение**: повтор до 2 раз с паузой 1 и 3 с; **запись**: без автоповтора | Блок «Не удалось загрузить данные» с «Повторить»; для записи — как ERR-2; ошибка логируется |
| ERR-5 | Сессия истекла | 401 | Попытка обновить токен; при неудаче — выход | «Сессия истекла, войдите снова»; после входа — возврат на ту же страницу |
| ERR-6 | Нет прав | `42501`, `P0403` | Действие не выполняется | Тост «Недостаточно прав для этого действия»; недоступные элементы скрыты заранее |
| ERR-7 | Объект не найден | `PGRST116`, `P0404`, 404 | — | «Операция удалена» или «Страница не найдена» со ссылкой на «Операции» |
| ERR-8 | Конфликт: объект изменён другим участником | `P0409` | Сохранение отклоняется | «Операция была изменена другим участником», данные перезагружаются, форма показывает новые значения |
| ERR-9 | Дубликат | `23505` | Объект не создаётся | Текст по объекту: «Такая категория уже есть», «Такой тег уже есть» |
| ERR-10 | Нарушение связи | `23503` | Удаление не выполняется | «Нельзя удалить: есть связанные операции. Переместите в архив» |
| ERR-11 | Непредвиденная ошибка интерфейса | — | Экран не «падает» целиком | Граница ошибок с кнопкой «Перезагрузить раздел»; ошибка логируется |

### 6.2. Пустые состояния

| Экран | Состояние | Что показываем |
|---|---|---|
| Операции | нет операций в периоде | «В этом периоде пока нет операций» + «Добавить операцию» |
| Операции | поиск или фильтры без результатов | «Ничего не найдено» + «Сбросить» |
| Отчёты | нет операций выбранного типа | «За этот период расходов нет» / «…доходов нет», без диаграммы |
| Отчёты › Теги | нет операций с тегами | «Нет операций с тегами за этот период» |
| План | нет бюджетов | «Бюджетов пока нет» + «Создать бюджет» (для `owner`/`admin`) |
| Участники | только владелец | «Вы единственный участник» + «Пригласить» (для `owner`) |

### 6.3. По функциям

| Функция | Негативный сценарий | Поведение |
|---|---|---|
| Вход | неверный пароль | «Неверный email или пароль», поле пароля очищается; после серии неудач — пауза по лимиту Supabase Auth |
| Регистрация | email уже занят | «Этот email уже зарегистрирован. Войти?» со ссылкой |
| Приглашение | просрочено, отозвано или использовано | «Приглашение недействительно. Попросите новую ссылку» |
| Приглашение | пользователь уже в семье | «Вы уже состоите в семье. Чтобы принять приглашение, выйдите из неё в настройках профиля» |
| Приглашение | в семье уже 10 участников | «В семье уже максимум участников» |
| Категории | дубликат названия | ERR-9 |
| Категории | удаление с операциями | «Удалить» заменено на «В архив» с пояснением (FR-2.5) |
| Категории | архивирование последней подкатегории | «У категории должна остаться хотя бы одна подкатегория» |
| Операция | сумма ≤ 0, > 2 знаков, слишком большая | «Введите сумму больше 0 с точностью до копеек» |
| Операция | дата позже сегодняшней | «Дата не может быть в будущем» |
| Операция | подкатегорию архивировали, пока форма была открыта | «Подкатегория больше недоступна, выберите другую» |
| Теги | 11-й тег | «Не более 10 тегов на операцию» |
| Период | конец диапазона раньше начала | «Применить» неактивна, «Дата окончания раньше даты начала» |
| Бюджет | нет элементов или сумма 0 | Сохранение невозможно, подсказка у поля |
| Удаление семьи | введённое название не совпадает | Кнопка «Удалить навсегда» неактивна |

### 6.4. Логирование

Ошибки ERR-4 и ERR-11 пишутся в `console.error` в JSON (уровень, время, экран, код) и в таблицу
`client_errors` (только вставка). Суммы, комментарии, email и имена в логи не попадают.
Централизованный сбор и анализ логов — в ДЗ6.
